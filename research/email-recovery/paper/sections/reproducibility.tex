\section{Open science: artifacts, reproducibility and threats to validity}\label{app:repro}

The artifacts are the paper's repository: the circuit, the contracts, the
wallet, the alert service and the mocks, the Lean model, the evaluation's
scripts and results, the claim ledger, and the sources of this paper and its
slides. Every artifact builds from the repository with one command, run from its
root after \texttt{git submodule update --init}, which fetches Perch at the
pinned commit. Table~\ref{tab:repro} lists them. The circuit commands install
Perch's pinned nargo and Barretenberg, checking each download against a
pinned SHA-256, and fail if the active versions differ from the pins. The
Lean model pins its Lean release in \texttt{lean-toolchain} and has no
library dependencies. The document build runs \texttt{latexmk} inside a TeX
Live image pinned by digest, checks the claim ledger (every measured figure
must occur in its measurement files), and fails on any undefined reference
or citation; continuous integration runs it on every
change, and runs the Lean build, the circuit tests, the contracts' tests and
the local-network attack suite on the changes that touch them. Re-running a
measurement regenerates its evidence, and the documents regenerate from it:
the attack suite rewrites its results, the evaluation's tables and the
figures that move from run to run (each run draws new keys and proofs, which
moves a vote's fee by a few stroops), and the next document build typesets
them, so the build passes after any run whose rows have their expected
outcomes.

\paragraph{Threats to validity.}\label{sec:eval-threats}
Every email is signed by a mock in its provider's published layout, and DNS,
the sending and push services, the enclave and the custodians are mocks; the
real-mail corpus checks the parser, not each provider's outbound recovery
mail. No registry addition leaves its timelock during a network run, so
network votes use the pin, and scenarios needing an active key run on the
test host, which runs the same contracts but is not a network; so does the
recovery with everything archived. The local network closes about one ledger
a second while reporting a 5-second target, so there a 120{,}960-ledger delay
lasts about 34 hours; close-time windows are unaffected. A scenario reports
only the first layer that refuses it. Timing comes from one shared machine,
testnet figures from one period, and the alert rows show mechanisms, not
people.
