## R-docs-F3 — The documented app-grant revocation remedy reaches a disabled wallet operation

- Source: R-docs (finding)
- Jev improves: 0.94
- Jev defect / severity: requirement_or_code / medium
- Locations: nido/docs/RUNBOOKS.md:294-297, nido/docs/DEFERRED.md:62-66, nido/packages/frontend/src/components/SessionKeyCard.ts:72-93, nido/packages/frontend/src/lib/signing/operationBuilders.ts:116-123, nido/packages/frontend/src/lib/signing/operationBuilders.test.ts:97-101

The runbook tells an owner at the signer/rule cap to revoke an app grant, and the deferral register presents that as the current workaround. The wallet's Revoke button still creates a remove-context-rule request. buildOperation unconditionally throws for that descriptor because Perch requires whole-document apply_doc writes; the existing unit test explicitly expects this refusal. This migration gap is not declared in the scoped deferral materials.

**Recommendation:** Make Revoke read the current document and revision, remove the selected grant and any now-unused signer declaration, preserve recovery settings, and submit apply-policy-doc with that revision. Until fixed, document an exact working whole-document removal procedure and mark the button's limitation explicitly.
