## R-zk-F3 — Nido's stale-source invariant overstates which document changes invalidate an attempt

- Source: R-zk (finding)
- Jev improves: 0.97
- Jev defect / severity: description_only / medium
- Locations: nido/docs/SECURITY_INVARIANTS.md:100, nido/vendor/perch/crates/perch-recovery/src/contract.rs:236-239, nido/vendor/perch/crates/perch-recovery/src/contract.rs:808-823, nido/crates/integration-tests/tests/it/recovery_rules.rs:473-487, nido/vendor/perch/docs/recovery/spec.md:660-668

R7 says an attempt is invalidated if the applied document changed since it opened. The implementation checks only whether the current document identity differs at promotion. Ordinary document changes that retain the recovery configuration do not bump the controller epoch. Therefore A -> B -> A before the final initiation evidence leaves an attempt opened under A promotable with its previously collected evidence. The cited Nido test only checks A -> B followed by promotion; it does not establish the stronger historical-change claim. Perch's detailed T4 rule accurately describes the narrower equality check.

**Recommendation:** Rewrite R7 to say that the current applied-document identity must differ from the recorded source when promotion is attempted. Explicitly document the A -> B -> A case and add a regression for it. If invalidation on every intervening change is intended instead, record and enforce a monotonically increasing document generation at begin and promotion.
