## R-docs-F3 — Nido DEFERRED.md miscounts Perch-owned items and omits Perch's 'Completion input-byte binding' deferral

- Source: R-docs (finding)
- Jev improves: 0.97
- Jev defect / severity: description_only / medium
- Locations: nido/docs/DEFERRED.md:8-17, nido/vendor/perch/docs/DEFERRED.md:9-12, nido/vendor/perch/docs/DEFERRED.md:353-392, nido/ARCHITECTURE.md:213-218

Nido DEFERRED says 'Perch owns the first eight items… The last item is Nido's', but it lists nine Perch-owned items plus one Nido item. Perch's register has a tenth entry, 'Completion input-byte binding': rcv_sync consumes a completion marker by canonical identity without re-checking the consuming apply_doc's input bytes, so a leftover marker lets an owner-authorized apply of a differently spelled target be classified as a completion (running revocation, nullifier spend and epoch bump). Nido's register, which claims to give 'Nido's side of each', omits it; both registers list 'the two-digest recovery target binding' as implemented, and ARCHITECTURE §4 presents the completion binding as complete.

**Recommendation:** Add a 'Completion input-byte binding' section to nido/docs/DEFERRED.md with Nido's side, fix the item count, and qualify ARCHITECTURE §4 and the 'two-digest binding is implemented' sentence (the bytes check is in enforce only, not at marker consumption).
