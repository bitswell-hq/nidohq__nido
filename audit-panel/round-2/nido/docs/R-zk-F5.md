## R-zk-F5 — ARCHITECTURE.md attempt state diagram contradicts Perch spec §6.2 on what becomes Invalidated

- Source: R-zk (finding)
- Jev improves: 1.00
- Jev defect / severity: description_only / medium
- Locations: nido/ARCHITECTURE.md:238-252, nido/vendor/perch/docs/recovery/spec.md:524-552, nido/vendor/perch/crates/perch-recovery/src/contract.rs:800-817

The diagram has 'Collecting --> Invalidated: epoch change, a sibling is authorized, or the lost-key source changed'. Per spec §6.2 and the controller, Invalidated is stored for exactly one cause (T4 finding a changed lost-key source, promote()); epoch changes and sibling authorization are derived deadness (is_live via epoch/invalidate_below) and the stored state stays Collecting.

**Recommendation:** Replace the edge with 'Collecting --> Invalidated: lost-key source changed at promotion' and add a note that epoch change or a sibling's authorization makes a Collecting attempt dead without changing its stored state (read attempt_live).
